# 24 — 뉴스 모듈 개선 설계 (요약·키워드 신뢰도)

작성: 2026-07-24 · 상태: **설계(구현 전, 승인 대기)**

사용자 지적: "전부 뉴스를 가져오고 중복만 없애는 것 같다. AI 요약이나 중요한 키워드를
뽑는 기능이 없어 보인다." → 뉴스 파이프라인 전 모듈 점검 + 개선 설계.

방향(사용자 확정): **A. 규칙기반 강화 먼저 → B. LLM 요약 나중에 선택적 추가.**

> **착수 시 우선순위 변경(2026-07-24).** 사용자가 구현 착수 시 "뉴스링크로만 남기고
> 한글로 번역된 요약본이 최우선"이라고 재확정 — Phase A 순서를 바꿔 **번역 표시(A1 확장)를
> 최우선으로 먼저 구현**하고, 나머지 A2~A6(키워드 오탐 수정·레이더·종목사전·중복병합·
> 피드필터)는 이어서 진행한다. 상세는 §2-A0, 구현 상태는 §3 표 참고.

---

## 1. 점검 결과 — 체감은 절반만 맞다

실데이터(저장소 400건, 2026-07-24 실측)로 확인한 결론: 분석 기능은 **계산은 되는데
대부분 화면에 안 나오거나 품질이 낮다.** "그냥 가져와서 중복만 없앤다"는 인상은 이 때문.

### 데이터 흐름(현행)
```
news_collector(RSS 7소스) → news_validator(중복/결측/미래시각)
  → news_repository(HTML 제거·정규화·병합 400건 유지)
  → news_categories(지역+키워드→6분류→4탭 배타)
  → news_levels(L1/L2/L3 규칙 점수) · news_entities(관련종목) · themes(빈도)
  → news_v2 생성기 → docs/news/index.html(+날짜 아카이브)
```

### 확인된 문제(근거 포함)

**N1. 한줄요약이 수집돼 있는데 목록에 안 보인다**
393/400 기사에 원문 추출 요약(`summary`)이 있는데, `_macros_v2/news.html`의
`article_row`는 **제목만** 렌더한다. design/03 §1-5는 기본 모드(72px)에서 "한줄요약 1줄"을
명시하지만 구현에 그 줄이 없다. → 사용자가 요약을 볼 수단이 아예 없다.

**N2. 키워드 레이더 카드가 미구현**
design/03 §3-5가 "최근 24시간 키워드 상위 6개 + 빈도 바"를 카드로 정의했으나 뉴스
페이지에 없다. `themes.py`(빈도 계산)는 **모닝리포트에서만** 소비된다. → "중요한 키워드를
뽑는 기능"이 없어 보이는 직접 원인.

**N3. 키워드/테마 매칭 오탐이 심각(실측)**
`extract_themes` 결과 `AI 80건`인데 대표 예시가 `"I will definitely claim Social Security"`.
부분문자열 `"ai"`가 **claim·email·maintain·available** 등 영어 단어에 걸린다. 한글
키워드는 문제없지만 영문 짧은 키워드(`ai`, `chip`)가 단어 경계를 안 봐 대량 오탐.
→ 키워드 신뢰도 자체가 무너져 있음.

**N4. 관련종목 태그가 빈약**
37/400건만 태깅. `config/entities.py` 사전이 ~20종목뿐 → 대부분 기사에 종목 연결 없음.

**N5. 동일 제목·다른 링크 중복 생존**
"매경이 전하는 세상의 지식"이 2건 남는다. 중복 제거가 링크 해시 기준이라 같은 기사의
다른 URL(구글뉴스 리다이렉트 등)을 못 잡는다. → 게재 카운터·리스트 신뢰도 저하.

**N6. 피드 잡음**
구글뉴스 RSS가 한국 경제 피드에 영어·비경제 기사를 섞어 넣는다(N3의 오탐과 상승작용).

## 2. 개선 설계 — Phase A(규칙기반, 무료) / Phase B(LLM, 선택)

### Phase A — 규칙기반 강화 (비용 0, no-AI 원칙 유지)

**A1. 한줄요약 목록 표시 (N1)**
`article_row`에 요약 1줄 추가(1줄 말줄임, `text.secondary`). 요약이 제목과 거의 같으면
(구글뉴스가 제목을 요약으로 반복하는 경우) 생략 — 중복 노출 방지.

**A2. 키워드 매칭 단어경계 수정 (N3)**
영문 키워드는 부분문자열이 아니라 단어 경계(`\bai\b`) 매칭으로 교체. 한글은 교착어라
경계 개념이 달라 현행 부분문자열 유지하되, 2글자 이하 영문 키워드는 경계 필수.
`news_categories`·`themes`·`news_entities` 세 곳이 같은 매칭 유틸을 공유하도록 추출
(`calculators/keyword_match.py` 신설) — 오탐 수정을 한 곳에서.

**A3. 키워드 레이더 구현 (N2)**
`themes.py`를 뉴스 페이지에도 연결. design/03 §3-5대로 최근 24시간 게재 기사 키워드
상위 6개 + 무채색 빈도 바 카드. A2 수정 후의 정확한 빈도를 쓴다(오탐 제거가 선행).

**A4. 종목 사전 확장 (N4)**
`config/entities.py`를 시총 상위 + 사용자 관심 유니버스(config/universe.py 참고)로 확장.
전종목은 오탐이 커 하지 않는다(design/21 §3 원칙 유지) — 코스피200/코스닥 대형주 중심.

**A5. 제목 유사 중복 병합 (N5)**
`news_validator`/`news_repository`에 제목 정규화(공백·출처접미사 제거) 기준 2차 중복
제거 추가. 완전 동일 정규화 제목만 병합(느슨한 유사도는 오병합 위험이라 배제).

**A6. 피드 잡음 필터 (N6)**
구글뉴스 결과에 경제 키워드 게이트를 두거나, 신뢰 소스 우선. 최소 개입으로 시작해
A2/A3 효과를 먼저 본 뒤 필요 시 강화.

### Phase B — LLM 요약 (선택, 비용 소액, 나중 단계)

no-AI 원칙을 **뉴스 브리핑에 한해** 완화. GitHub Actions 빌드 시점에 Claude API로
당일 L3/L2 기사에서 "오늘의 브리핑 3줄"과 테마 한줄 코멘트를 생성.

- **키**: `ANTHROPIC_API_KEY`를 GitHub Secret으로. 미설정이면 Phase A 규칙기반 브리핑으로
  자동 폴백(결측 문법 — 키 없다고 페이지가 깨지지 않는다).
- **비용**: 하루 1~2회 × 소량 입력 → 일 수 센트. 캐시로 재호출 억제.
- **저작권**: 원문 복제가 아니라 사실 요약만(현행 추출식과 동일 원칙). 링크는 항상 원문.
- **투명성**: LLM 생성물은 "AI 요약" 라벨을 명시(규칙기반 산출과 구분).
- Phase A 완료·안정화 후 착수. 본 문서는 방향만 확정하고 상세는 Phase A 결과를 보고 채운다.
